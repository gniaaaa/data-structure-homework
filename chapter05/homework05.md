第五题

## (1) 用三元组表实现推荐权重矩阵 C = A × B

### 数学模型

- A：用户-物品交互矩阵，m 行 × n 列，A[i][k] 是用户 i 对物品 k 的交互分值（点击/收藏/评分）；
- B：物品相似度矩阵，n 行 × n 列，B[k][j] 是物品 k 与物品 j 的相似度；
- C：推荐权重矩阵，C[i][j] = Σ(k=1..n) A[i][k] · B[k][j]。

物理含义很直白：用户 i 对他交互过的物品 k 有兴趣，就把这份兴趣按相似度 B[k][j]
「传播」给与 k 相似的物品 j，累加起来就是该用户对 j 的推荐权重。
所以这题的本质就是**稀疏矩阵乘法**，只是乘出来的结果要当推荐分数用。

### 数据结构

沿用课件第 17 页的三元组顺序表（下标从 1 开始，data[1..t] 按行序、同行按列序排列）：

```c
#define MAXSIZE 100              // 非零元最大个数 u
typedef double elemtype;         // 权重是小数

typedef struct tuple {
    int i, j;
    elemtype v;
} TupleNode;

typedef struct sparmattp {
    int m, n, t;                 // m:行数; n:列数; t:非零元素数目
    TupleNode data[MAXSIZE + 1]; // data[1..t]
} TSMatrix;
```

```c
TSMatrix MultiplySparse(TSMatrix A, TSMatrix B);   // 返回推荐权重矩阵 C
```

### 算法：按行累加

```
for i = 1 .. A.m:                       // 一次只算 C 的一行
    清空 acc[1..C.n] 和 has[1..C.n]
    for A 中每个 i 行的非零元 (i, k, v):
        for B 中每个 k 行的非零元 (k, j, w):
            acc[j] += v * w;  has[j] = true
    for j = 1 .. C.n:
        if has[j] 且 acc[j] != 0:
            把 (i, j, acc[j]) 追加到 C.data 末尾
```

三个要点：

1. **只对非零元做乘加**。A、B 各有 tA、tB 个非零元，稠密乘法要做 m·n·n 次乘加，
   而 99% 的乘数都是 0，纯属浪费；这里只处理真正的非零组合。
2. **结果天然有序**。逐行处理 + 行内按列压缩，使 C 自动满足「按行序、同行按列序」，
   不需要像「逐元素插入法」那样反复查找插入位置或事后排序。
3. **累加数组代替查找**。若每算出一个乘积就去 C 里线性查找 (i,j) 是否已存在，
   复杂度会退化到 O(tA·tB·tC)；用 acc[] 累加，把「合并同类项」变成 O(1) 的数组访存。

实现时还要处理两个边界：A.n != B.m 时维度不匹配，返回空矩阵；
某行累加后 acc[j] 恰好被正负抵消为 0 时，不写入 C（题目要求只保留权重 ≠ 0 的元素）。

### 复杂度

| 项目 | 复杂度 | 说明 |
|:---|:---|:---|
| 时间 | O(m·tA + tA·tB + m·p) | 每行扫一遍 A 的三元组，每个 A 非零元再扫一遍 B 的三元组 |
| 空间 | O(p + tC) | 一个长度为 p 的累加数组 + 结果三元组表 |

对比稠密乘法 O(m·n·p)：当 tA ≪ m·n、tB ≪ n·p 时优势是数量级的。
若 A 的规模很大，还可把 B 按行建索引（行起始位置数组），把内层扫描从 O(tB)
降到「该行非零元个数」，进一步降到 O(tA·avg_nnz)。

### 运行结果（用课件第 41 页的数据验证）

```
A（3 用户 × 4 物品，5 个非零元）
   1 1 1.0   1 3 0.8   2 2 0.5   2 4 0.7   3 1 0.9
B（4 × 4，7 个非零元）
   1 1 1.0   1 3 0.6   2 2 1.0   3 1 0.6   3 3 1.0   4 2 0.8   4 4 1.0

C = A × B（3 × 4，6 个非零元）
   用户1-物品1  1.48      用户1-物品3  1.40
   用户2-物品2  1.06      用户2-物品4  0.70
   用户3-物品1  0.90      用户3-物品3  0.54
```

与课件第 41 页给出的 6 个权重逐一相等，其余 6 个位置为 0，未进入三元组表。

**这里有一处课件笔误需要说明**：课件的 B 表只列了 6 个非零元
（(0,0)、(0,2)、(1,1)、(2,0)、(2,2)、(3,1)，0 基），漏掉了对角元 B[3][3] = 1.0。
可是课件自己算的「用户 1 - 物品 3 = 0.7 × 1.0 = 0.7」只有在 B[3][3] = 1.0 时才成立；
相似度矩阵的对角元本来就都该是 1.0（物品与自身完全相似），所以 B 实际有 7 个非零元。
按 7 个跑，C 就与课件完全一致；按 6 个跑，C(2,4) 会算成 0。程序里我补上了这一项并注了说明。

## (2) 用真实/模拟数据跑一次推荐

### 数据从哪来

这一问要求「爬取常去的购物网站」，我没有直接去爬，原因有两个：
一是登录态下的订单、浏览记录属于个人信息，爬取和二次使用涉及《个人信息保护法》；
二是主流电商的 robots 协议与用户协议都禁止自动化抓取。
可行的替代是：用平台自带的「我的订单导出」、公开推荐数据集（Amazon Reviews、
MovieLens、Taobao UserBehavior），或手工构造小样本。下面用手工构造的 5 用户 × 6 物品数据，
保证每一步都能复核。

### 构造 A 和 B

物品：i0 咖啡豆、i1 手冲滤纸、i2 磨豆机、i3 保温杯、i4 机械键盘、i5 显示器。
交互分值取 1~5（点击 1、收藏 3、购买 5）：

| 用户 | i0 | i1 | i2 | i3 | i4 | i5 |
|:---|:-:|:-:|:-:|:-:|:-:|:-:|
| u0（我） | 5 | 4 | 3 | 0 | 0 | 0 |
| u1 | 4 | 3 | 0 | 5 | 0 | 0 |
| u2 | 0 | 0 | 0 | 0 | 5 | 4 |
| u3 | 0 | 2 | 0 | 0 | 3 | 5 |
| u4 | 3 | 0 | 4 | 0 | 0 | 0 |

B 用列向量余弦相似度计算：

```
B[k][j] = Σ_i A[i][k]·A[i][j] / (‖A[:,k]‖ · ‖A[:,j]‖)
```

得到的主要相似度：

| 物品对 | 相似度 | 依据 |
|:---|:---|:---|
| i4 键盘 - i5 显示器 | 0.937 | u2、u3 都同时买了两者 |
| i0 咖啡豆 - i1 滤纸 | 0.840 | u0、u1 的强共现 |
| i0 咖啡豆 - i2 磨豆机 | 0.764 | u0、u4 的共现 |
| i0 咖啡豆 - i3 保温杯 | 0.566 | u1 买咖啡豆又买保温杯 |
| i1 滤纸 - i4 键盘 | 0.191 | 仅 u3 偶发共现（弱相关） |

### 推荐结果

用 (1) 的程序算 C = A × B，取 u0 这一行（已交互的是 i0、i1、i2，推荐时应过滤掉）：

| 候选物品 | 权重 | 是否已交互 |
|:---|:---|:---|
| i3 保温杯 | 5.057 | 否 → **推荐** |
| i5 显示器 | 1.160 | 否 |
| i4 机械键盘 | 0.764 | 否 |
| i0 / i1 / i2 | 10.652 / 9.539 / 8.601 | 是，过滤 |

**是否符合预期？** 第一名 i3 保温杯是合理的：我买了咖啡豆、滤纸、磨豆机，
另一位同样买咖啡豆的用户还买了保温杯，把他这份兴趣传播过来，正好补上「带咖啡出门」的场景。
这一条我确实想要。

但 i5 显示器、i4 键盘也冒出来了，权重只有 0.76~1.16。它们的来源是 u3
「买滤纸又买键盘」这一次偶发共现给出的 0.191 相似度。也就是说，
**弱相关被一阶传播放大成了候选**。如果不加阈值就按分数取 Top-N，推荐结果里就会混进
跟咖啡毫无关系的东西——这正是纯 A×B 方案最典型的噪声问题。

### 对这个结果的想法

1. **相似度要截断和归一化**。B 里 0.19 这种值应置 0（阈值 0.3），
   同时对 B 的行做归一化（除以物品度数或用 IDF 加权），否则热门物品的相似度普遍虚高。
2. **一阶传播只能覆盖「同品类」**。A×B 把咖啡器具内部的关联挖得很好，
   但键盘和显示器之间的强相似（0.937）对我的推荐毫无影响，因为我在那个连通分量里没有任何交互。
   要跨品类，得再加用户侧协同（UserCF：先算用户相似度矩阵 U = A×A^T，再算 U×A），
   或者做二阶传播 A×B×B。
3. **冷启动无解**。新上架物品在 B 中没有行（没人交互过就无法算相似度），
   一阶传播永远推不出它，只能靠内容特征（标题/图像 embedding）兜底。
4. **分值本身太粗**。现在只用 1/3/5 三档，丢掉了时间和频次信息；
   实际应乘时间衰减 exp(-λ·Δt)，并把「浏览-收藏-购买」设成不同权重。
5. **工程上不该用三元组顺序表直接扫**。本题规模小没问题，
   但真实矩阵 t 上亿时，O(tA·tB) 的行扫描不可接受，应改用 CSR + 倒排索引
   （按 k 直接取到 B 的第 k 行），或按 k 分块并行；A 更新时只增量重算受影响的行，
   而不是整表重乘。静态批量运算用三元组表、动态更新用十字链表，这个取舍和第二题是一致的。
6. **评价与多样性**。光看分数排序会让推荐越来越窄（全是咖啡器具），
   可用 MMR 做多样性打散；离线用 Recall@K、NDCG 评估，线上看点击率和转化，
   再做 A/B 实验，而不是凭「看起来对不对」判断。

一句话总结：三元组乘法把「推荐」还原成了一次稀疏矩阵乘，机制清楚、可解释、算得快，
但它本质上只是「相似物品的加权投票」，要想真正好用，还得在相似度归一化、
用户侧协同、时间衰减和冷启动上做加工。
